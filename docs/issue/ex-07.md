## 備考

- branchは `ex-07` とする。`54-release-docs` の通常branch名ではなく、ユーザー指定の特別task名を優先する。
- Gate作成またはGate分割の指示はないため、Gate planは作成しない。本issueが単独の実装契約である。
- このissueでいう「ソースコードを変更しない」には、サイト表示コードだけでなく、変換script、browser script、test実装、workflow、package設定、依存関係、生成データ、静的アセットを含む。テスト方針を説明するMarkdownは文書正規化対象である。
- `.codex/agents/*.toml` は実行設定を変えず、AI Ops文書の説明と矛盾するprompt表現を正規化する場合だけ対象にできる。不要なら変更しない。
- Markdownのみの変更を想定するため、`npm run check` と `npm run build` は実行しない。`npm run format:md` と `npm run check:md` を文書検証として実行する。

## レビュー指摘 1

### 指摘事項

- `docs/testing.md` が実行コマンドとテスト種別の列挙に留まり、後続の開発者が意味のあるテストを設計・レビューするための選択基準として不足している。
- Webキャラクターシートのような複雑な対話機能では、E2Eを代表的な利用者経路とブラウザ固有の境界へ絞り、計算、状態遷移、永続化、Componentの表示契約をlogic、hook、Component testへ分解する原則を継承できるようにする必要がある。
- 新規のUI、hook、ロジック、script testでVitestを推奨し、Node testは既存の変換、schema、build contractなどNode実行環境そのものを検証する用途に限定する方針が明示されていない。

### 判定

- source: human
- classification: valid
- local validation: `package.json`はVitestを`tests/components`、`tests/hooks`、`tests/scripts`で実行し、Node testを`tests/node`とbuild contractで実行する。現行のcharacter-sheetは多数のComponent / hook testと、代表操作に絞った`tests/e2e/character-sheet.spec.ts`を併用している。`docs/testing.md`にはこの分担と、新規テストの選択基準が不足している。

### 対応方針

- `docs/testing.md`に、テスト対象ごとの推奨配置・ランナー・E2Eへ残す条件を明記する。
- character-sheetの既存構造を一般化し、複雑な対話機能はpure logic、hook、Component、E2Eの順に責務を分け、E2Eを代表フローと実ブラウザ境界へ限定する原則を記載する。
- 新規のUI、hook、pure logic、script testはVitestを標準とし、新規に`node:test`を選ばず、既存Node testは保守対象としてこのissueで移行しないことを明記する。
- 文書のみを修正し、テスト実装、`package.json`、workflow、ソースコードは変更しない。
