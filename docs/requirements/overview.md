# 要件概要

サイト全体の目的、基本方針、初期スコープ外の要件を扱う。

## 0. 文書の位置づけ

本ドキュメントは、ネオン・アンダーレルムTRPGの無料公開用ルールサイトの公開済み機能と継続運用の要件定義である。

本サイトは、制作者が継続的にルール本文、データ、リリースノートを更新し、Git連携によって静的サイトとして公開できることを最優先とする。

要件は `docs/requirements.md` を索引とし、詳細は `docs/requirements/*` に分割して管理する。

milestone-01の履歴とクローズtaskは `docs/issue/milestone-01/plan.md` に置く。現在のtaskは承認済みissueを正本とし、計画履歴によって既存実装を変更しない。

`docs/out-of-scope.md` は初期スコープ外項目の正本とする。要求とスコープ外の記述が矛盾する場合は、現行実装、最新のユーザー指示、承認済みissueを照合して同じtaskで正規化する。

## 1. 基本方針

### 1.1 サイトの目的

ネオン・アンダーレルムTRPGのルール、世界観、キャラクターメイキング、Webキャラクターシート、データ、アイテム、戦闘ルール、成長ルールをWebサイトとして無料公開する。

初期公開スコープでは、PL向けの基本ルール、参照データ、キャラクターを試作できる体験を主対象とする。

1st stepの目的は、ルールサイト公開の初回告知を見た人がなるべく長くサイトを読み、「遊んでみたい」と思えることとする。完了は、初回告知時点でPLが遊ぶ判断と参加準備をするために十分なコンテンツが公開されている状態と定義する。

シナリオ本文、キャンペーン本文は初期スコープ外とする。

### 1.2 最重要方針

本サイトでは、機能の多さよりも、制作者が継続的にコンテンツを管理・更新・公開できることを優先する。

以下を重視する。

- ルール本文を編集しやすいこと
- スキル、アイテムなどの表形式データを更新しやすいこと
- 公開手順が重すぎないこと
- Git連携によって自動公開できること
- Codex等のコード生成支援に修正依頼しやすい構造であること
- 将来のV1.5修正やデータ更新に耐えられること
- 1画面ずつ完成状態まで持っていけること

### 1.3 公開済み構成の維持方針

ページ、データ、検索、Webキャラクターシートは静的サイトの公開機能として実装済みである。変更時は、対象画面ごとに必要なデータ、Component、本文、design notes、検証を同じissueで確認する。

ページ作成では、原則として以下の順序を採用する。

1. データ変更では、変換仕様、schema、生成JSON、対応testを確認する。
2. UI変更では、design notesと対象VRTを先に確認する。
3. pageやComponent変更では、既存route、GitHub Pagesのsubpath、検索への影響を確認する。
4. Visual Reviewのactual screenshotとbaseline更新は、定義済みworkflowとユーザー承認に従う。

## 17. 初期スコープ外

以下は初期スコープ外とする。

- シナリオ本文
- キャンペーン本文
- キャンペーン管理機能
- NPC一覧・詳細
- キャラクター作成ウィザード
- ダイスローラー
- 戦闘シミュレーター
- 戦闘処理支援ツール
- CMS
- Firebase Authenticationとcharacter sheet cloud persistence以外のログイン・認証
- 投稿・コメント機能
- character sheet cloud persistence以外のDB
- character sheet cloud persistence backend以外のサーバーサイド処理
- 外部検索サービス連携
- PDF自動生成
- PWA対応
- 多言語対応
- 高度な画像最適化
- パンくずリスト
- 個別OGP画像生成
- 高度なアニメーション
- 過剰なUIライブラリ

Cloudflare Web Analyticsのmanual beaconは、公開用deployだけで出力する最小限のアクセス解析として初期スコープ内である。custom event、閲覧者単位の追跡、他providerとの併用は初期スコープ外とする。

シナリオ進行ルールページ `/rules/scenario-play` は、シナリオ本文を掲載するページではなく、PL向けのシナリオ進行ルールを説明するページとして扱う。
